# Функциональная справка по расширению хранилища

## Цель и статус

Это авторитетная функциональная спецификация расширения браузера Vault. В нем документируется контракт продукта: данные, которые пользователь может настроить, точное поведение, создаваемое конфигурацией, общедоступный язык пользовательских правил и ограничения, которые к нему применяются.

Это намеренно не краткое руководство. Учебник на веб-сайте — это путь обучения. Этот документ предназначен для людей, которым необходимо настраивать, тестировать, обслуживать, проверять или воспроизводить видимое пользователю поведение Vault.

Код является канонической истиной, когда этот документ и продукт не совпадают. Имена в этом документе, где это возможно, используют сохраненный/общедоступный словарь продукта. Такое слово, как «возвраты», означает возвращаемое значение, доступное для пользовательского правила; он не обещает результата на уровне браузера, если браузер или страница отклоняют запрошенное действие.

## 1. Граница продукта

Vault — это WebExtension для управления фокусом. Его единицей конфигурации является **группа блоков**. Группа может:

- принять решение о блокировке веб-сайта верхнего уровня, страницы платформы, создателя, сообщества, сервера, канала или учетной записи;
- скрыть настроенные поверхности платформы или соответствующие карточки подачи;
- измерять время, проведенное в соответствующем объеме;
- применить расписание, защиту от замораживания или временную остановку, если это поддерживается типом группы;
- запустить пользовательское правило JavaScript с помощью API событий;
- показывать таймер на странице, панель, сообщение или журнал страницы;
- перенаправлять, перемещаться, закрывать вкладку браузера или поддерживать черный список сайтов, созданный только для сеанса;
- при необходимости участвовать в локально подключенном кластере Vault Bridge.

Vault действует только внутри профиля браузера, в котором он установлен, и только там, где браузер разрешает запуск сценария содержимого. Это не так:

- установить родное приложение или расширение для браузера;
- блокировать приложения операционной системы;
- обходить запросы разрешений браузера, ограничения частного просмотра или собственную модель безопасности веб-сайта;
- гарантировать скрытие на основе селектора, когда сторонняя платформа меняет свой DOM;
- сделать состояние пользовательских правил переносимым между профилями, если пользователь не экспортирует/не настраивает его отдельно;
- предоставить сетевой брандмауэр, прокси-сервер, контроль учетных записей или службу родительского контроля.

Везде используется следующая терминология:

| Срок | Значение |
| --- | --- |
| Группа | Один объект конфигурации с независимым именем. Имена должны быть уникальными в пределах расширения без учета регистра. |
| Группа сайтов | Обычная группа, список доменов которой является ее основным условием соответствия. |
| Группа платформ | Обычная группа, специализирующаяся на YouTube, TikTok, Facebook, Instagram, Twitch, Reddit, Discord или Twitter/X. |
| Пользовательская группа | Группа, владеющая правилом JavaScript и регистрациями его событий. Его правила определяют его поведение. |
| Матч | Страница, элемент ленты или поверхность платформы удовлетворяют настроенным условиям группы. |
| Активный | Группа включена, соответствует ее расписанию и в настоящее время не отложена. Пользовательские группы не управляются обычным пользовательским интерфейсом расписания. |
| Блокировать | Предотвратите возможность использования текущей страницы верхнего уровня, обычно путем перенаправления на ее резервную цель. |
| Скрыть | Удалить или скрыть элемент/карточку на отображаемой в данный момент странице. Скрытие не является блокировкой сети. |
| Резервный URL | Цель перенаправления для конкретной группы. Если это значение пусто, используется глобальный резервный вариант. |
| Эффект разрешения/исключения | Вердикт карты-платформы, который спасает соответствующий контент от правил скрытия с более низким приоритетом. Это не общий белый список веб-сайтов. |

## 2. Групповая модель и общий жизненный цикл

Каждая сохраненная группа имеет стабильный идентификатор, имя, тип, включенный флаг и общие поля политики. Новая обычная группа включена по умолчанию. Группу можно выбрать, сохранить с помощью автосохранения редактора, переупорядочить, экспортировать, импортировать, заморозить, разморозить, отложить, отключить или удалить.

### 2.1 Порядок и перекрытие

Одной и той же странице может соответствовать более одной группы. Vault оценивает сохраненные группы от конца отображаемого списка к началу. При разработке перекрывающихся правил рассматривайте элементы с более низким значением в списке как более поздние совпадения с более высоким приоритетом.

При обычной блокировке сайта верхнего уровня любая применимая группа блокировки может сделать страницу недоступной. Для фильтрации карточек подачи каскад платформы использует порядок и эффект каждой соответствующей группы: более позднее сопоставление разрешения/исключения может спасти элемент от предикатов блокировки с более низким приоритетом. Такое поведение исключения ограничено поверхностью фильтрации платформой; он не отменяет обычную блокировку всей страницы сайта.

### 2.2 Включенное состояние

Отключенные группы сохраняются, но не участвуют в обычном сопоставлении, таймерах, расписаниях или обычных операциях повтора. Отключение пользовательской группы также выгружает ее активные регистрации. Повторное включение не превращает несохраненный текст в активное пользовательское правило; запустите правило для загрузки сохраненного источника.

### 2.3 Общие поля

| Поле | Значение и ограничения |
| --- | --- |
| Имя | Непустой, обрезанный и уникальный без учета регистра в пределах этой конечной точки. Мост также идентифицирует подключаемые группы по имени и типу, поэтому стабильные имена имеют значение. |
| Включено | Включает или отключает обычное сопоставление. |
| Поведение | Мгновенная блокировка, блокировка после допуска или таймер/отсчет. Пользовательские группы используют собственное правило, а не этот обычный селектор поведения. |
| Разрешенные минуты | Положительное число, используемое в режиме блокировки после разрешения. Новые группы по умолчанию составляют 15 минут. |
| Сбросить интервал часов | Положительное число, используемое обычными группами по времени. Новые группы по умолчанию работают 24 часа. |
| Активные дни | С понедельника по воскресенье. Обычная группа неактивна, если не выбран текущий местный день недели. |
| Временные окна | Ноль или более окон местного времени, по одному на строку, записываются как ЧЧММ-ЧЧММ. |
| Режим заморозки | «Нет», «Заморожено», «Строго заморожено» или «Родительски заморожено». |
| Политика отсрочки | Разрешает ли группа повтор, с контролем продолжительности/задержки/перезарядки/подтверждения для обычных групп. |
| Резервный URL | Назначение используется, если группа блокирует страницу. |
| Перейти к следующему | Если это предусмотрено в редакторе, запрашивает обычный поток блокировки пройти мимо заблокированной цели, а не оставаться на ней. |

### 2.4 Нормальное групповое поведение

Обычный редактор предлагает три варианта поведения:

| Поведение | Функциональный результат |
| --- | --- |
| Немедленно заблокировать | Как только группа активна и соответствует, обычное решение о блокировке страницы принимается немедленно. |
| Блокировать через несколько минут | Соответствующее время просмотра видимой страницы учитывается в соответствии с настроенным лимитом. Когда лимит исчерпан, обычная группа блокируется до тех пор, пока период ее использования не будет сброшен или группа не станет неактивной/отложенной по другим причинам. |
| Таймер (обратный отсчёт, без блокировки) | Соответствующее время видимой страницы записывается и может отображаться. Этот режим никогда не блокируется только потому, что его таймер достигает значения. |

Использование по времени основано на времени просмотра видимой страницы. Он не предназначен для тарификации времени, пока страница скрыта на фоновой вкладке. Интервал сброса — это скользящий интервал политики для обычной временной группы. Обычные таймеры независимы по группам.

### 2.5 Расписания

Расписание распространяется на обычные группы. Пользовательская группа не имеет обычного пользовательского интерфейса расписания и считается активной с точки зрения ее JavaScript; правило само должно налагать любые желаемые временные условия.

Политика активного дня оценивается по местному времени:

1. Если текущий день недели не выбран, обычная группа неактивна.
2. Если действительные временные окна не указаны, активный день означает полный день.
3. Если указаны допустимые окна, текущее местное время должно быть хотя бы в одном окне.

Каждое окно имеет точный формат ЧЧММ-ЧЧММ, например 09:00-12:00. Часы должны быть от 00 до 23, минуты от 00 до 59, а начало должно быть раньше окончания в тот же день. Окно включает начало и исключает конец. Окна между полуночью, например 23:00-01:00, недействительны. Пустые строки игнорируются, а повторяющиеся окна сворачиваются.

### 2.6 Отложить

Для обычной группы повтор — это временное неактивное состояние, состоящее из трех фаз:

| Фаза | Результат |
| --- | --- |
| В ожидании | Запрошенная отсрочка существует, но не началась из-за задержки активации. Группа по-прежнему активна. |
| Активный | Группа временно неактивна на время ожидания. |
| Время восстановления | Откладывание завершилось, группа снова активна, и новый откладывание не может начаться, пока не истечет время восстановления. |

Поля конфигурации нормальной группы:

| Поле | Правило |
| --- | --- |
| Разрешить отложить | Если выключено, обычный режим повтора не может быть запущен. |
| Продолжительность повтора | Позитивные минуты. Новая нормальная группа принимает глобальное значение по умолчанию, первоначально 30. |
| Задержка активации | Ноль или более минут. Пусто означает ноль. |
| Время восстановления | Ноль через пять минут. Пусто означает ноль. |
| Подтверждения | Неотрицательное целое число. Продукт требует выполнения большого количества подтверждающих действий, прежде чем удовлетворить запрос. |

В группе «Пользовательская» кнопка «Отложить» рассматривается только как событие ввода. Vault генерирует для этой группы пользовательское событие snoozePress; оно не применяет обычный запас длительности/задержки/перезарядки от имени правила. Пользовательское правило может использовать событие, собственное постоянство, панель, таймер или вообще не выполнять никаких действий.

### 2.7 Заморозка

Заморозка защищает группу от обычных изменений конфигурации и от обычных изменений режима ожидания. Выбор режима фиксации в селекторе не замораживает группу сам по себе; действие замораживания применяет выбранный режим.

| Режим | Функциональный контракт |
| --- | --- |
| Замороженный | Группа заблокирована до тех пор, пока не завершится обычный поток подтверждения разблокирования продукта. |
| Строгая замороженная | Группу нельзя разморозить, пока не истечет срок ее строгой заморозки. Продолжительность должна быть больше нуля и не более 72 часов; новая группа по умолчанию составляет 24 часа. |
| Родительский заморожен | Для управления замораживанием/размораживанием требуется пароль опекуна. В диалоговом окне конфигурации используется шестизначный пароль. |

Замороженные группы нельзя редактировать через обычные поля. Кластер, связанный мостом с автономным участником, также может заблокировать элементы управления замораживанием, поскольку Vault не может безопасно координировать замороженное состояние в кластере. Заморозка — это защита от обычных операций пользовательского интерфейса; он не превращает профиль браузера в неизменную границу безопасности.

### 2.8 Импорт, экспорт, очистка и сброс

Экспорт создает совместимое представление выбранной группы. Импорт проверяет и нормализует совместимые данные группы перед их добавлением. Имена импортированных групп по-прежнему должны быть уникальными. Удалить группу удаляет эту группу и ее обычное состояние использования/откладывания. Очистить удаляет все группы после подтверждения.

Возврат к настройкам по умолчанию — это операция **глобальных настроек**. Он отбрасывает предпочтения всего расширения; это не заменитель импорта/экспорта, и к нему следует относиться как к разрушительному.

## 3. Типы групп и соответствующий контракт

### 3.1 Группа веб-сайтов по умолчанию

Группа сайтов владеет списком веб-сайтов, разделенным строками. Записи нормализуются в форме хост/домен. Запись хоста соответствует этому хосту и всем его поддоменам.

| Настройка | Результат |
| --- | --- |
| Заблокировать все, кроме этих сайтов | Список представляет собой черный список. Соответствующий хост заблокирован. |
| Заблокируйте все, кроме этих сайтов | Список является разрешенным. Каждый хост, которого нет в списке, блокируется. Таким образом, пустой белый список является преднамеренной блокировкой всей сети. |
| Заблокировать домашнюю страницу | Применяет политику группы к настроенной начальной/домашней поверхности браузера, где доступен этот элемент управления. |
| Резервный URL | Назначение перенаправления для блока. Пустое значение группы возвращается к глобальному значению по умолчанию. |

Обычный список доменов группы сайтов — это единственный декларативный список всего сайта, предоставляемый редактором. Вместо этого группы платформ соответствуют своей собственной платформе и настроенным условиям платформы.

###3.2 Группы видеоплатформы

YouTube, TikTok, Facebook, Instagram и Twitch — это группы видеоплатформ. Каждый из них ограничен своим собственным хостом платформы. Группа может ориентироваться на форму контента, область действия автора/учетной записи, домашнюю ленту платформы и дополнительные элементы управления скрытием элементов.

Общие авторские режимы:

| Режим | Результат |
| --- | --- |
| Все | Не ограничивать по автору; другие настроенные оси определяют совпадение. |
| Включить | Сопоставьте только перечисленных нормализованных авторов/аккаунтов. |
| Исключить | Сопоставить всех обнаруженных авторов/аккаунтов, кроме перечисленных записей. |
| Никто | Нет совпадения с автором. Это намеренное несоответствие авторской оси. |
| Тег включает | Сопоставьте авторов с любым указанным тегом, если Сейф может их классифицировать. Неизвестные/несекретные создатели не открываются. |
| Исключить тег | Сопоставляйте авторов без настроенных тегов, если Сейф может их классифицировать. Неизвестные/несекретные создатели не открываются. |

Выбор формы контента зависит от платформы:

| Платформа | Формы контента |
| --- | --- |
| Ютуб | Все страницы, короткие видео, длинные видео, посты. |
| Тик Ток | Все страницы, короткие видео. |
| Фейсбук | Все страницы, ролики, видео, посты. |
| Инстаграм | Все страницы, ролики, видео, посты. |
| Твич | Все страницы, клипы, стримы/VOD, страницы каналов. |

Vault нормализует вводимые автором данные. Редактор принимает обычную форму дескриптора/канала/страницы платформы и поддерживаемые URL-адреса профилей. Он может отклонять некорректные записи или показывать их как недействительные, вместо того, чтобы молча превращать их в другую цель.

Варианты скрытия поверхности не зависят от блокировки верхнего уровня. Они влияют только на текущий пользовательский интерфейс платформы и могут перестать работать, когда платформа меняет свою разметку.

| Платформа | Отправлено выбор скрытых элементов |
| --- | --- |
| Ютуб | Навигация в Shorts, полки, карточки, реклама на главной странице, рекламные поверхности и комментарии. Опция, связанная с рекламой, отображает предупреждение, поскольку скрытие рекламы может противоречить условиям платформы. |
| Тик Ток | Изучите навигацию. |
| Фейсбук | Навигация по барабанам и поверхности барабанов. |
| Инстаграм | Барабаны и исследование навигации/поверхностей. |
| Твич | Просмотрите навигацию. |

При сопоставлении тегов авторов YouTube используются местные/доступные классификации каналов. Отсутствующая классификация не становится блоком только потому, что был выбран режим тегов.

### 3.3 Реддит

Группа Reddit применяется только на Reddit. Его сущность — субреддит. Входные данные Subreddit принимают обычную форму сообщества и нормализуют ее перед сопоставлением.

Режимы субреддита:

| Режим | Результат |
| --- | --- |
| Все | Подайте заявку на Reddit без ограничений списка субреддитов. |
| Включить | Применить к перечисленным субреддитам. |
| Исключить | Применить ко всем субреддитам, кроме перечисленных. |
| Никто | Не применять ни к одному субреддиту. |

Поставляемая опция скрытия поверхности скрывает навигацию «Популярное/Все». Поведение фид-карточек зависит от структуры карточек, которую Reddit в настоящее время обнаруживает.

### 3.4 Дискорд

Группа Discord применяется только на страницах Discord/Discordapp. Его целью является идентификатор сервера или пара сервер/канал. Целевой редактор принимает нормализованные значения пути к каналу Discord.

| Режим | Результат |
| --- | --- |
| Все | Подайте заявку в Discord без ограничений по списку целей. |
| Включить | Применяется только к перечисленным целевым серверам или серверам/каналам. |
| Исключить | Применить ко всем целям, кроме перечисленных. |
| Никто | Применить ни к какой цели. |

Discord в настоящее время не имеет возможности скрыть элемент в обычном профиле платформы.

### 3.5 Твиттер / X

Группа Twitter/X действует в X/Twitter. Он может применяться ко всем учетным записям или использовать общие режимы учетных записей, описанные для видеоплатформ, с нормализованным вводом дескриптора/ссылки на профиль.

Поставляемые варианты скрытых элементов: «Обзор», «Сообщения», «Грок», «Тенденции» и продвигаемые элементы ленты. Как и в случае со всеми поверхностными элементами управления на основе селектора, изменение разметки X может повлиять на их работу.

### 3.6 Декларативные поля настраиваемой группы

Пользовательская группа в основном запускает свой исходный код JavaScript. Он не использует обычный селектор поведения или обычный пользовательский интерфейс расписания. Тем не менее, он может содержать список доменов при импорте или настройке с помощью совместимых данных:

- непустой пользовательский черный список может участвовать в обычном решении по всей странице сайта;
- Пользовательский белый список может участвовать, даже если он пуст, что приводит к полномасштабной декларативной блокировке;
- ненастроенная Пользовательская группа случайно не блокирует страницы только потому, что у нее есть правило;
- Пользовательские таймеры никогда не блокируются сами по себе; правило явно решает, следует ли блокировать по истечении времени таймера.

### 4.1 Интерфейс редактора и панели обратной связи

Редактор расширений имеет постоянный список групп и редактор выбранных групп. Список групп предоставляет средства выбора типа группы, «Добавить», «Очистить», выбрать, включить переключение и порядок перетаскивания. Размер его разделителя можно изменить. Редактор выбранной группы предоставляет поля, специфичные для группы, и действия экспорта/импорта группы.

Редактор автоматически сохраняет обычные изменения полей после периода глобального устранения дребезга. Об ошибках проверки сообщается в виде обратной связи о статусе или всплывающем сообщении; недопустимые нормальные значения не преобразуются автоматически в несвязанные настройки. Замороженная группа отключает обычные элементы управления редактированием.

Расширение также имеет следующие видимые пользователю поверхности обратной связи:

| Поверхность | Функциональное назначение |
| --- | --- |
| Руководство по эксплуатации | Открывает эту ссылку в расширении. |
| Выбор языка | Выбирает язык интерфейса расширения. |
| Настройки | Открывает глобальные настройки, описанные выше. |
| Обратная связь о статусе/тосте | В отчетах сохраняются, импортируются, проверяются и отображаются результаты действий. |
| Наложение таймера на странице | Показывает активные элементы обычного таймера/обратного отсчета и пользовательские таймеры, находящиеся в их области отображения. Несколько элементов могут сосуществовать. |
| Поверхность журнала на странице | Получает вызовы пользовательского журнала, предупреждений и ошибок, если это разрешено глобальными настройками. |
| Пользовательский журнал | Живой журнал активности для записей, созданных правилами и видимых во всплывающих окнах. Его можно очистить и загрузить. |

Для пользовательских групп в поле «Правила» хранится исходный текст. Команда «Выполнить сначала» выполняет предварительную проверку синтаксиса правила и загружает источник только в случае успеха. Редактор также выполняет анализ локального источника при изменении текста. Видимый элемент управления **Let AI Code** открывает поле подсказки и копирует пакет генерации кода, содержащий запрос пользователя, текущее правило и созданную ссылку на текущий API настраиваемых правил. Он не связывается со службой искусственного интеллекта и не меняет правило автоматически.

Элемент управления «Шаблоны» открывает браузер шаблонов. Поставляемый шаблон имеет заголовок, описание, теги, параметры и созданный предварительный просмотр. Его применение заменяет текущий текст Правил после подтверждения. Каталог шаблонов, поставляемый в данный момент, пуст; браузер остается доступным для будущих шаблонов, и его нельзя рассматривать как источник активных правил.

## 5. Язык специальных правил

### 5.1 Формы источника правил

Источником пользовательской группы является JavaScript. При нажатии **Выполнить** Сейф удаляет предыдущие регистрации группы и состояние, созданное предыдущим активным источником, а затем загружает новый источник.

Источником может быть:

1. a function expression accepting events and helpers; or
2. голые операторы, использующие предоставленные события (или устаревшие события) и вспомогательные переменные.

```js
// Function-expression form
(events, helpers) => {
  events.on("openWebEvent", "welcome", (event, h) => {
    h.log("Opened", event.url);
  });
}
```

```js
// Bare-statement form
events.on("openWebEvent", "welcome", (event, h) => {
  h.log("Opened", event.url);
});
```

Run выполняет предварительную проверку синтаксиса JavaScript и только в случае успеха делает текущий источник активным. Сохранение текста и запуск текста намеренно отличаются: правило можно сохранить, не становясь активным источником событий.

Активный источник выгружается при повторном запуске, отключении, удалении или явной остановке пользовательской группы. При повторном запуске очищаются обработчики, таймеры, панели, сегмент сохраняемости и предикаты платформы, созданные правилом, перед началом регистрации. Восстановление в песочнице может перезагрузить активный источник; поэтому авторы правил должны сделать регистрацию идемпотентной.

### 5.2 Модель выполнения и безопасные предположения

Custom rules are event registrations, not a continuous script loop. Register handlers during rule initialization, then respond to events.

Каждый обработчик получает:

```js
(event, helpers) => {
  // event: the currently dispatched event object
  // helpers: the public Vault Custom-rule API
}
```

Обработчики событий, запускаемых по убыванию числового приоритета; равный приоритет использует порядок регистрации. Обработчик можно заменить, повторно зарегистрировав тот же тип события и идентификатор. В одной настраиваемой группе может быть зарегистрировано не более 1000 обработчиков.

Vault ограничивает активную работу одного обработчика примерно одной секундой. Три превышения крайнего срока для одной и той же группы в течение одной минуты изолируют правило: Vault отключает его, а не повторно запускает проблемный обработчик. Не используйте ожидания занятости, неограниченные циклы, синхронный опрос или огромное количество мутаций/логов на одно событие.

За одну отправку Vault принимает не более:

| Товар | Максимум |
| --- | --- |
| Записи журнала правил | 200 |
| Размещенные события | 64 |
| DOM-операции | 256 |
| Действия/намерения | 256 |
| Панели на группу | 24 |
| Управление на одной панели | 32 |
| Параметры выбора/радиоуправления | 64 |

Лишние записи журнала, опубликованных событий, операций DOM и намерений могут быть удалены. Специальное правило не должно зависеть от доставки лишних записей.

### 5.3 Встроенные типы событий

Следующие строки типа события встроены. Правило также может использовать собственную непустую строку типа, если она не начинается с подчеркивания.

| Тип события | Когда оно будет отправлено | Важные данные |
| --- | --- | --- |
| тикСобытие | Общий периодический тик с глобальной настройкой тик-рейта. | Текущий контекст страницы/вкладки, если он доступен. Используйте опцию регистрации интервалаMs, чтобы ограничить скорость отдельного обработчика. |
| openWebEvent | Для правила становится доступной страница верхнего уровня. | URL-адрес, имя хоста, идентификаторы вкладок/страниц, время. |
| закрытьWebEvent | Страница/вкладка верхнего уровня закрывается. | Контекст URL/имени хоста, если он доступен. |
| вебChangedEvent | Надежная навигация верхнего уровня, включая перезагрузку одного и того же URL-адреса. | данные содержат предыдущий URL-адрес/имя хоста и флаги навигации, такие как isFirstLoad, isReload и SameDomain. |
| таймер закончился | Пользовательский таймер переходит в состояние с истекшим сроком действия. | данные: timerId, displayName, направление, currentMs. Он доставляется только группе владельцев таймера. |
| отложитьПресс | Пользователь нажимает кнопку «Начать повтор» для этой пользовательской группы. | Правилу принадлежит ответ; обычный возврат к повтору не выполняется. |
| панельСобытие | Отрисованная пользовательская панель имеет взаимодействие. | Поля данных и удобства включают информацию о панели/элементе управления/событии/значении. |
| локальное событие | Запрошенное действие с локальным файлом завершено. | Поля данных и удобства включают requestId, путь, результат, байты, записи и ошибку. |
| страницаHeartbeatEvent | Пульсация видимой страницы примерно каждые 250 мс, пока вкладка видна. | elapsedMs — прошедшее время видимой страницы. Пользовательские таймеры с ограниченной областью действия автоматически используют его даже без зарегистрированного обработчика. |

### 5.4 API реестра событий

Первым аргументом источника в стиле функции является реестр событий. В исходном виде с простым оператором и события, и событие ссылаются на этот реестр.

| Метод | Контракт |
| --- | --- |
| events.on(type, id, handler, options) | Register a handler. Returns true when accepted, false for invalid/capped registrations. |
| events.register(type, id, handler, options) | Alias of on. |
| events.off(type, id) | Unregister a handler. Returns whether something was removed. |
| events.unregister(type, id) | Alias of off. |
| events.unregisterAll(type) | Remove all handlers owned by this group for that event type. Returns the number removed. |
| events.getEvent(type, id) | Return the registered function for this group/id, or null. |
| events.getEvents(type) | Return an object mapping this group's handler ids to functions. |
| events.countRegistered(type) | Return this group's number of registrations for type. |
| events.emit(type, data, options) | Queue a synthetic event. |
| events.post(type, data, options) | Alias of emit. |

Необязательный объект параметров обработчика поддерживает:

| Вариант | Значение |
| --- | --- |
| приоритет | Числовой порядок. Более высокие значения выполняются раньше более низких значений. По умолчанию 0. |
| интервалMs | Положительное число. Только для TicketEvent подавляет вызовы до тех пор, пока не пройдет столько времени с момента предыдущего вызова обработчика. |

Синтетические события по умолчанию относятся к области группы: их получают только обработчики, принадлежащие группе-отправителю. Используйте {scope: "global" }, чтобы отправить событие каждому правилу, зарегистрировавшему тот же тип. Не используйте нижнее подчеркивание в имени события; оно зарезервировано.

### 5.5 Объект события

Каждый обработчик получает изменяемый объект события с общими полями:

| Поле/метод | Контракт |
| --- | --- |
| тип | Строка типа события. |
| идентификатор группы | Идентификатор специальной группы получателя. |
| tabId, pageId | Идентификаторы браузера, если они доступны; в противном случае ноль. |
| URL, имя хоста | Текущий URL-адрес верхнего уровня и имя хоста или пустые строки. |
| время | Копия объекта времени отправки или значение NULL. |
| данные | Полезная нагрузка, специфичная для события, или значение NULL. |
| предотвратитьПо умолчанию() | Отмечает отправку как действие блокировки страницы. Страница перенаправляется на текущую ссылку/результат перенаправления, если таковой существует; в противном случае Vault использует обычный путь выхода/резервного пути. |
| стопПропагация() | Останавливает последующие обработчики для текущей отправки событий. |
| setResult(значение) | Сохраняет числовой или строковый результат. Непустая строка рассматривается как цель перенаправления; результат 1 подавляет накопленный в противном случае результат предотвращения по умолчанию. |
| получитьРезультат() | Возвращает результат, установленный этим объектом события, или значение null. |
| сообщение(тип, данные, параметры) | Поставьте в очередь синтетическое событие с теми же правилами области, что и для Events.post. |
| setRedirectLink(url) | Установите URL-адрес перенаправления для этой отправки. Возвращает false только для нестроковых входных данных. |
| getRedirectLink() | Прочтите URL-адрес перенаправления этой отправки или пустую строку. |
| закрыть(идентификатор) | Запросить закрытие вкладки. Число — это идентификатор вкладки, строка идентифицирует URL-адрес, а пропущенное значение указывает на активную вкладку. |
| блок(идентификатор) | Добавьте шаблон динамической блокировки сайта только для сеанса. Если идентификатор строки отсутствует, используйте имя хоста события. |
| разблокировать (идентификатор) | Удалите шаблон динамической блокировки сайта только для сеанса. Если идентификатор строки отсутствует, используйте имя хоста события. |

Обработчик может прикреплять к событию произвольные дополнительные свойства. Прочтите их через event.custom или напрямую по присвоенному имени, пока этот объект события активен. Они не являются постоянными состояниями и не являются хранилищем перекрестных событий.

Для PanelEvent добавлены следующие удобные поля: PanelId, controlId, eventName, значение, значения, ключ, код и keyInfo.

Для localFileEvent добавлены следующие удобные поля: имя события, действие, путь, путь к каталогу, идентификатор запроса, ОК, текст, значение, записи, существует, байты и ошибка.

### 5.6 Точки входа в помощник

Объект helpers имеет следующие прямые свойства:

| Точка входа | Значение |
| --- | --- |
| helpers.now | Current dispatch timestamp in milliseconds. |

Таймер обратного хода останавливается на нуле и выдает timerEnded при переходе на ноль. Оно остается нулевым до тех пор, пока правило не изменит/сбросит его. ## 8. Рецепты действий по собственным правилам

Следующие примеры являются спецификациями публичного состава, а не учебным пособием.

### 8.1 Перенаправление первой страницы

```js
(events, helpers) => {
  events.on("openWebEvent", "redirect-distracting-search", (event, h) => {
    const domain = h.getDomainHelper();
    if (!domain.isSearchPage(event.url)) return;
    event.setRedirectLink(h.getRedirectionHelper().createMessageUrl("Return to your planned task."));
    event.preventDefault();
  });
}
```

### 8.2 Обратный отсчет видимого времени с явной блокировкой

```js
(events, helpers) => {
  const timer = helpers.getTimerHelper();
  timer.create({
    id: "reading-budget",
    displayName: "Reading budget",
    direction: "backward",
    currentMs: 10 * 60 * 1000,
    scope: (url) => url.includes("example.com")
  });

  events.on("timerEnded", "stop-at-zero", (event) => {
    if (event.data?.timerId !== "reading-budget") return;
    event.setRedirectLink("about:blank");
    event.preventDefault();
  });
}
```

### 8.3 Изменение предиката фида с панели

```js
(events, helpers) => {
  const panel = helpers.getPanelHelper();
  const youtube = helpers.platform("youtube");

  panel.create({
    id: "feed-filter",
    title: "Feed filter",
    controls: [{
      id: "hide-sponsored",
      type: "toggle",
      label: "Hide sponsored items",
      value: true,
      onChange: (event, h) => {
        const api = h.platform("youtube");
        if (event.value) {
          api.hide("videos", (item) => item?.sponsored === true);
        } else {
          api.show("videos");
        }
        api.rescan();
      }
    }]
  });

  youtube.hide("shorts", () => true);
}
```

Предикаты должны быть записаны для значений моментального снимка/элемента платформы, предоставляемых активной поверхностью платформы. Если платформа не может надежно идентифицировать поле, предикат должен не открыться, а не предполагать, что значение истинно.

## 9. Протокол запроса локальной папки

Операции с локальной папкой не являются немедленным вводом-выводом файлов. Полная функциональная последовательность:

1. Пользователь выбирает папку в глобальных настройках.
2. Правило ставит запрос в очередь и получает идентификатор запроса.
3. Vault запрашивает разрешение авторизованной папки для выполнения операции.
4. Vault отправляет localFileEvent в ту же пользовательскую группу.
5. Обработчик сопоставляет event.requestId с исходным идентификатором запроса.

Успешное чтение завершается текстом для текстовых файлов или значением для JSON. Список возвращает записи. Существует, прибыль существует. Write/append предоставляет байты, где это применимо. Неудача обеспечивает ОК, ложь и ошибку. Правила никогда не должны предполагать, что выбранная папка остается авторизованной после перезагрузки, перезапуска браузера или отзыва разрешений.

## 10. Семантика безопасности и отказов по специальным правилам

### 10.1 Ошибки компиляции и запуска

Ошибка компиляции отчетов о синтаксисе. Run также может сообщить об ошибке выполнения во время регистрации. Если источник, подобный функции, содержит синтаксическую ошибку, Vault не будет молча относиться к нему как к безобидным простым операторам.

Пустой источник не имеет обработчиков. Оно действует как неактивное настраиваемое правило, но не выполняет настроенных настраиваемых действий.

### 10.2 Ошибки обработчика

Исключение из одного обработчика изолировано от общей отправки событий. Это диагностический вывод; это не приводит к волшебному успеху последующих обработчиков. Используйте узкие обработчики и регистрируйте ошибки, требующие принятия мер.

### 10.3 Карантин

Сейф может помещать пользовательскую группу в карантин после неоднократного превышения крайнего срока или превышения срока во время регистрации. Карантин отключает группу и записывает причину ее завершения. Исправьте исходный код, сохраните его и явно запустите снова, чтобы восстановить активные регистрации.

### 10.4 Ограничения браузера/страницы

Ни одно пользовательское правило не получает неограниченные API расширений. В частности:

- селектор DOM не может найти ничего на измененной платформе;
- навигация, закрытие вкладок и действия на экране зависят от возможностей браузера;
- расширение не может открывать родные приложения;
- Для операций с локальной папкой требуется папка, предоставленная пользователем, и поддерживаемые типы файлов;
- обработчик событий не может полагаться на невидимую страницу, продолжающую генерировать тактовые сигналы видимого времени;
- страница может перезагружаться, перемещаться по ней, быть удалена или сделать недействительным сценарий содержимого независимо от правила;
- динамические блокировки сайта, созданные правилами, представляют собой действия в состоянии сеанса, а не постоянные изменения группы сайтов.

## 11. Мост через веб-приложение

Мост не является обязательным. Он подключает клиент расширения браузера к совместимому локальному концентратору Vault. Расширение браузера является клиентом; собственное приложение Vault предоставляет концентратор. Фиксированной локальной конечной точкой является ws://127.0.0.1:8787, требуется совместимость протокола.

Состояния подключения: «Выключено», «Подключение», «Отключено», «Подключено» и «Ошибка». Если клиент включен, Vault сначала проверяет быстро, а затем продолжает медленные попытки повторного подключения до тех пор, пока не подключится или пользователь не отключит его. Соединение само по себе не объединяет все группы.

### 11.1 Связывание групп

Группы можно связать только в том случае, если их имя и тип совпадают и они подходят для связывания. Пользователь явно выбирает/связывает участвующие программы. Связанная группа образует кластер. При отключении данные локальной группы остаются нетронутыми; он останавливает живую синхронизацию.

Мост синхронизирует общую скалярную политику для поддерживаемых связанных групп, включая обычный режим блокировки, значения разрешения/сброса, настройки повтора, активные дни/окна, состояние/выбор/продолжительность заморозки, политику домашней страницы, настройку белого списка, резервный URL-адрес и политику перехода к следующему. Он также координирует использование и состояние повтора для членов кластера.

Мост не обещает, что каждое поле, специфичное для продукта, переключатель платформы, пользовательский исходный текст или специфичные для браузера возможности можно будет перенести в другую программу. Группа может оставаться локальной и несвязанной, даже если мост подключен.

Кластеры «замороженного моста» требуют, чтобы все соответствующие члены были онлайн для действий в замороженном состоянии, требующих скоординированной мутации. Соединение — это локальный транспорт, а не облачный резервный канал или канал удаленного управления.

## 12. Контрольный список проверки для сопровождающих

Используйте этот контрольный список при аудите выпуска или воспроизведении поведения:

1. Убедитесь, что группа имеет непустое уникальное имя, правильный тип, включенное состояние и предполагаемый список/порядок.
2. Для обычных групп подтвердите активный день недели, допустимое окно местного времени, отсутствие активного повтора и незафиксированное состояние редактирования.
3. Для группы сайтов проверьте точный хост, поддомен и (для белого списка) хост вне списка.
4. Для группы платформ отдельно проверьте соответствие на уровне страницы, целевое соответствие элемента/карточки, авторский режим, режим формы контента и скрытие каждой включенной поверхности.
5. Для обычных групп с таймером проверьте накопление видимых страниц, истечение срока действия разрешения или подсчет неблокирующего поведения, а также интервал сброса.
6. Для пользовательских правил запустите проверку синтаксиса, «Выполнить», проверьте количество/журналы обработчиков, проверьте каждое зарегистрированное встроенное событие, затем протестируйте перезагрузку/навигацию.
7. Проверьте каждый пользовательский таймер на границах области действия и на нуле; убедитесь, что любой блок явен в правиле.
8. Тестовые панели с каждым значением элемента управления, отключенным состоянием, действием отправки/отмены/закрытия и обработчиком PanelEvent.
9. Прежде чем добиться успеха, проверьте сбой локальной папки: папка не выбрана, разрешение отозвано, неверный путь, неподдерживаемое расширение, затем разрешено чтение/запись.
10. Прежде чем полагаться на синхронизацию или заморозку координации, протестируйте отключенное и включенное соединение моста, связанную/несвязанную группу и автономного члена кластера.
