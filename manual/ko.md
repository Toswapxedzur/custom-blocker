# Vault 확장 기능 참조

## 목적 및 현황

이는 Vault 브라우저 확장에 대한 신뢰할 수 있는 기능 사양입니다. 여기에는 사용자가 구성할 수 있는 데이터, 구성에 따른 정확한 동작, 공개 사용자 정의 규칙 언어 및 이에 적용되는 제한 사항 등 제품 계약이 문서화되어 있습니다.

의도적으로 빠른 시작 가이드가 아닙니다. 웹사이트 튜토리얼은 학습 경로입니다. 이 문서는 Vault의 사용자에게 표시되는 동작을 구성, 테스트, 유지 관리, 감사 또는 재현해야 하는 사람들을 위한 것입니다.

이 문서와 제품이 일치하지 않는 경우 코드는 정식 진실입니다. 이 문서의 이름은 가능한 경우 제품의 저장/공개 어휘를 사용합니다. "반품"과 같은 단어는 사용자 정의 규칙에 사용할 수 있는 반환 값을 의미합니다. 브라우저나 페이지가 요청된 작업을 거부하는 경우 브라우저 수준 결과를 약속하지 않습니다.

## 1. 제품 경계

Vault는 초점 제어 WebExtension입니다. 구성 단위는 **블록 그룹**입니다. 그룹은 다음을 수행할 수 있습니다.

- 최상위 웹사이트, 플랫폼 페이지, 제작자, 커뮤니티, 서버, 채널 또는 계정을 차단해야 하는지 결정합니다.
- 구성된 플랫폼 표면 또는 일치하는 피드 카드를 숨깁니다.
- 일치하는 범위에서 소요된 시간을 측정합니다.
- 해당 그룹 유형이 지원하는 경우 일정, 동결 방지 또는 임시 일시 중지를 적용합니다.
- 이벤트 API를 사용하여 사용자 정의 JavaScript 규칙을 실행합니다.
- 페이지 내 타이머, 패널, 메시지 또는 페이지 로그를 표시합니다.
- 리디렉션, 탐색, 브라우저 탭 닫기 또는 세션 전용 규칙으로 생성된 사이트 차단 목록 유지
- 선택적으로 로컬로 연결된 Vault 브리지 클러스터에 참여합니다.

Vault는 설치된 브라우저 프로필 내에서만 작동하며 브라우저가 컨텐츠 스크립트 실행을 허용하는 경우에만 작동합니다. 그렇지 않습니다:

- 기본 애플리케이션 또는 브라우저 확장을 설치합니다.
- 운영 체제 애플리케이션을 차단합니다.
- 브라우저 권한 프롬프트, 개인 탐색 제한 또는 웹사이트 자체 보안 모델을 우회합니다.
- 제3자 플랫폼이 DOM을 변경할 때 선택기 기반 숨김을 보장합니다.
- 사용자가 별도로 내보내거나 구성하지 않는 한 사용자 정의 규칙 상태를 프로필 간에 이식 가능하게 만듭니다.
- 네트워크 방화벽, 프록시, 계정 제어 또는 자녀 보호 서비스를 제공합니다.

다음 용어가 전체에서 사용됩니다.

| 기간 | 의미 |
| --- | --- |
| 그룹 | 독립적으로 이름이 지정된 구성 개체 1개. 이름은 확장명 내에서 고유해야 하며 대소문자를 무시합니다. |
| 사이트 그룹 | 도메인 목록이 주요 일치 조건인 일반 그룹입니다. |
| 플랫폼 그룹 | YouTube, TikTok, Facebook, Instagram, Twitch, Reddit, Discord 또는 Twitter/X에 특화된 일반 그룹입니다. |
| 사용자 정의 그룹 | JavaScript 규칙 및 해당 이벤트 등록을 소유한 그룹입니다. 그 규칙이 그 행동을 결정합니다. |
| 경기 | 페이지, 피드 항목 또는 플랫폼 표면이 그룹의 구성된 조건을 충족합니다. |
| 활성 | 그룹이 활성화되어 있고 일정에 적합하며 현재 일시 중지되어 있지 않습니다. 사용자 지정 그룹은 일반 일정 UI에 의해 관리되지 않습니다. |
| 블록 | 일반적으로 대체 대상으로 리디렉션하여 현재 최상위 페이지를 계속 사용할 수 없도록 방지합니다. |
| 숨기기 | 현재 렌더링된 페이지에서 요소/카드를 제거하거나 숨깁니다. 숨기는 것은 네트워크 차단이 아닙니다. |
| 대체 URL | 그룹별 리디렉션 대상입니다. 비어 있으면 전역 대체가 사용됩니다. |
| 허용/예외 효과 | 우선순위가 낮은 숨기기 규칙에서 일치하는 콘텐츠를 구출하는 플랫폼 카드 판정입니다. 일반적인 웹사이트 허용 목록이 아닙니다. |

## 2. 그룹 모델 및 공통 수명주기

저장된 모든 그룹에는 안정적인 ID, 이름, 유형, 활성화된 플래그 및 공통 정책 필드가 있습니다. 새로운 일반 그룹은 기본적으로 활성화됩니다. 그룹은 선택, 편집기의 자동 저장 동작에 의해 저장, 재정렬, 내보내기, 가져오기, 고정, 고정 해제, 일시 중지, 비활성화 또는 삭제될 수 있습니다.

### 2.1 순서와 중복

둘 이상의 그룹이 동일한 페이지와 일치할 수 있습니다. Vault는 표시된 목록의 끝부터 시작 부분까지 저장된 그룹을 평가합니다. 겹치는 규칙을 디자인할 때 목록에서 낮은 항목을 나중/더 높은 우선순위 일치로 처리합니다.

일반적인 최상위 사이트 차단의 경우 적용 가능한 차단 그룹이 페이지를 사용할 수 없게 만들 수 있습니다. 피드 카드 필터링의 경우 플랫폼 캐스케이드는 각 일치 그룹의 순서와 효과를 사용합니다. 나중에 일치하는 허용/예외를 사용하면 우선순위가 낮은 차단 조건에서 항목을 구할 수 있습니다. 이 예외 동작은 플랫폼 카드 필터링 표면으로 제한됩니다. 일반적인 전체 페이지 사이트 차단은 실행 취소되지 않습니다.

### 2.2 활성화된 상태

비활성화된 그룹은 유지되지만 일반 매칭, 타이머, 일정 또는 일반적인 다시 알림 작업에는 참여하지 않습니다. 사용자 정의 그룹을 비활성화하면 활성 등록도 언로드됩니다. 다시 활성화해도 저장되지 않은 텍스트가 활성 사용자 정의 규칙으로 바뀌지는 않습니다. 규칙을 실행하여 저장된 소스를 로드합니다.

### 2.3 공통 필드

| 필드 | 의미와 제약 |
| --- | --- |
| 이름 | 이 끝점 내에서 비어 있지 않고 잘리고 대소문자를 구분하지 않고 고유합니다. 또한 브리지는 이름과 유형별로 연결 가능한 그룹을 식별하므로 안정적인 이름이 중요합니다. |
| 활성화됨 | 일반 일치를 활성화하거나 비활성화합니다. |
| 행동 | 즉시 차단, 허용 후 차단 또는 타이머/카운트업. 사용자 지정 그룹은 이 일반적인 동작 선택기가 아닌 자체 규칙을 사용합니다. |
| 허용된 시간(분) | 허용 후 차단 동작에 사용되는 양수입니다. 새 그룹의 기본값은 15분입니다. |
| 간격 시간 재설정 | 시간이 지정된 일반 그룹에서 사용되는 양수입니다. 새 그룹의 기본값은 24시간입니다. |
| 활동일 | 월요일부터 일요일까지. 현재 현지 요일을 선택하지 않으면 일반 그룹은 비활성화됩니다. |
| 시간 창 | 0개 이상의 현지 시간 창(한 줄에 하나씩)은 HHMM-HHMM으로 작성됩니다. |
| 동결 모드 | 없음, 냉동, 엄격 냉동 또는 부모 냉동. |
| 스누즈 정책 | 그룹이 다시 알림을 허용하는지 여부(일반 그룹에 대한 지속 시간/지연/휴지/확인 제어 포함) |
| 대체 URL | 그룹이 페이지를 차단하는 경우 사용되는 대상입니다. |
| 다음으로 건너뛰기 | 편집기에 제공되면 일반 차단 흐름에 차단된 대상에 머물지 않고 지나가도록 요청합니다. |

### 2.4 일반적인 그룹 행동

일반 편집기는 세 가지 동작을 제공합니다:

| 행동 | 기능적 결과 |
| --- | --- |
| 즉시 차단 | 그룹이 활성화되고 일치하면 일반적인 페이지 차단 결정이 즉시 이루어집니다. |
| 몇 분 후에 차단 | 일치하는 페이지 표시 시간은 구성된 허용량에 대해 누적됩니다. 허용량이 소진되면 일반 그룹은 사용 기간이 재설정되거나 그룹이 비활성/일시 중지될 때까지 차단됩니다. |
| 타이머(카운트업, 차단 없음) | 일치하는 페이지 표시 시간이 기록되어 표시될 수 있습니다. 이 모드는 타이머가 값에 도달했다는 이유만으로 차단되지 않습니다. |

시간별 사용량은 표시된 페이지 시간을 기준으로 합니다. 페이지가 배경 탭에 숨겨져 있는 동안 시간을 ​​충전하려는 의도는 아닙니다. 재설정 간격은 일반 시간 그룹에 대한 롤링 정책 간격입니다. 일반 타이머는 그룹별로 독립적입니다.

### 2.5 일정

일정은 일반 그룹에 적용됩니다. 사용자 정의 그룹에는 일반 일정 UI가 없으며 JavaScript 목적상 활성인 것으로 간주됩니다. 규칙은 원하는 시간 조건 자체를 부과해야 합니다.

활성일 정책은 현지 시간을 사용하여 평가됩니다.

1. 현재 요일을 선택하지 않으면 일반 그룹은 비활성화됩니다.
2. 유효한 시간 창이 제공되지 않은 경우 활성 날짜는 하루 전체를 의미합니다.
3. 유효한 창이 제공되면 현재 현지 시간은 최소한 하나의 창에 있어야 합니다.

각 창의 정확한 형식은 HHMM-HHMM입니다(예: 0900-1200). 시간은 00~23분, 00~59분이어야 하며 시작은 같은 날 종료 이전이어야 합니다. 창은 시작을 포함하고 끝을 제외합니다. 2300-0100과 같은 자정 시간대는 유효하지 않습니다. 빈 줄은 무시되고 중복된 창은 축소됩니다.

### 2.6 스누즈

일반 그룹의 경우 다시 알림은 최대 3단계로 구성된 일시적인 비활성 상태입니다.

| 단계 | 결과 |
| --- | --- |
| 보류 중 | 요청한 다시 알림이 존재하지만 활성화 지연으로 인해 시작되지 않았습니다. 그룹은 여전히 ​​​​활성화되어 있습니다. |
| 활성 | 일시중지 기간 동안 그룹이 일시적으로 비활성화됩니다. |
| 쿨다운 | 다시 알림이 종료되고 그룹이 다시 활성화되며 재사용 대기시간이 만료될 때까지 다른 다시 알림을 시작할 수 없습니다. |

일반 그룹 구성 필드는 다음과 같습니다.

| 필드 | 규칙 |
| --- | --- |
| 일시 중지 허용 | 꺼져 있으면 일반 스누즈를 시작할 수 없습니다. |
| 스누즈 기간 | 긍정적인 분. 새 일반 그룹은 전역 기본값인 처음에는 30을 사용합니다. |
| 활성화 지연 | 0분 이상. 공백은 0을 의미합니다. |
| 쿨다운 | 0~5분. 공백은 0을 의미합니다. |
| 확인 | 음수가 아닌 정수입니다. 제품에서는 요청을 승인하기 전에 많은 확인 상호 작용이 필요합니다. |

사용자 정의 그룹은 다시 알림 버튼을 입력 이벤트로만 처리합니다. Vault는 해당 그룹에 대해 snoozePress라는 맞춤 이벤트를 내보냅니다. 규칙을 대신하여 일반 기간/지연/휴지 대체를 적용하지 않습니다. 사용자 정의 규칙은 이벤트, 자체 지속성, 패널, 타이머를 사용하거나 전혀 작업을 수행하지 않을 수 있습니다.

### 2.7 동결

동결은 일반적인 구성 변경 및 일반적인 다시 알림 변경으로부터 그룹을 보호합니다. 선택기에서 고정 모드를 선택해도 그룹 자체는 고정되지 않습니다. 고정 동작은 선택한 모드를 적용합니다.

| 모드 | 기능 계약 |
| --- | --- |
| 냉동 | 그룹은 제품의 일반적인 고정 해제 확인 흐름이 완료될 때까지 잠겨 있습니다. |
| 엄격한 냉동 | 엄격한 동결 기간이 경과할 때까지는 그룹을 동결 해제할 수 없습니다. 기간은 0보다 크고 72시간 이하여야 합니다. 새 그룹의 기본값은 24시간입니다. |
| 부모의 냉동 | 동결/해제 관리를 위해서는 보호자 비밀번호가 필요합니다. 구성 대화 상자에서는 6자리 비밀번호를 사용합니다. |

고정된 그룹은 일반 필드를 통해 편집할 수 없습니다. 오프라인 구성원이 있는 브리지 연결 클러스터는 Vault가 클러스터 전체에서 정지 상태를 안전하게 조정할 수 없기 때문에 정지 제어를 잠글 수도 있습니다. 동결은 일반적인 UI 작업에 대한 보호입니다. 브라우저 프로필을 변경할 수 없는 보안 경계로 바꾸지는 않습니다.

### 2.8 가져오기, 내보내기, 지우기 및 재설정

내보내기는 선택한 그룹의 호환 가능한 표현을 생성합니다. 가져오기는 호환되는 그룹 데이터를 추가하기 전에 유효성을 검사하고 정규화합니다. 가져온 그룹 이름은 여전히 ​​고유해야 합니다. 그룹 삭제는 해당 그룹과 일반적인 사용/일시 중지 상태를 제거합니다. 지우기는 확인 후 모든 그룹을 제거합니다.

기본값으로 재설정은 **전역 설정** 작업입니다. 확장 프로그램 전반의 기본 설정을 삭제합니다. 이는 수입/수출 대체품이 아니므로 파괴적인 것으로 취급되어야 합니다.

## 3. 그룹 유형 및 매칭 계약

### 3.1 기본 웹사이트 그룹

사이트 그룹은 줄로 구분된 웹사이트 목록을 소유합니다. 항목은 호스트/도메인 형식으로 정규화됩니다. 호스트 항목은 해당 호스트 및 모든 하위 도메인과 일치합니다.

| 설정 | 결과 |
| --- | --- |
| 이 사이트를 제외한 모든 사이트 차단 끄기 | 목록은 차단 목록입니다. 일치하는 호스트가 차단되었습니다. |
| 다음 사이트를 제외한 모든 사이트 차단 | 목록은 허용 목록입니다. 목록에 없는 모든 호스트는 차단됩니다. 따라서 빈 허용 목록은 의도적인 전체 웹 잠금입니다. |
| 홈페이지 차단 | 해당 컨트롤을 사용할 수 있는 구성된 브라우저 시작/홈 표면에 그룹의 정책을 적용합니다. |
| 대체 URL | 블록의 대상을 리디렉션합니다. 빈 그룹 값은 전역 기본값으로 대체됩니다. |

일반 사이트 그룹 도메인 목록은 편집자가 노출하는 유일한 선언적 전체 사이트 목록입니다. 대신 플랫폼 그룹은 자체 플랫폼 및 구성된 플랫폼 조건과 일치합니다.

### 3.6 사용자 정의 그룹 선언 필드

사용자 정의 그룹은 주로 JavaScript 소스를 실행합니다. 일반 동작 선택기나 일반 일정 UI를 사용하지 않습니다. 그럼에도 불구하고 호환 가능한 데이터를 통해 가져오거나 구성할 때 도메인 목록을 전달할 수 있습니다.

- 비어 있지 않은 사용자 정의 차단 목록은 일반 전체 페이지 사이트 결정에 참여할 수 있습니다.
- 사용자 정의 허용 목록은 비어 있는 경우에도 참여할 수 있으며 전체 웹 선언적 잠금을 생성합니다.
- 구성되지 않은 사용자 정의 그룹은 규칙이 있다는 이유만으로 실수로 페이지를 차단하지 않습니다.
- 맞춤 타이머는 스스로 차단하지 않습니다. 규칙은 타이머가 만료될 때 차단할지 여부를 명시적으로 결정합니다.

### 4.1 편집기 인터페이스 및 피드백 표면

확장 편집기에는 영구 그룹 목록과 선택된 그룹 편집기가 있습니다. 그룹 목록은 그룹 유형 선택기, 추가, 지우기, 선택, 토글 활성화 및 끌기 순서를 제공합니다. 구분선의 크기를 조정할 수 있습니다. 선택한 그룹 편집기는 그룹별 필드와 그룹 내보내기/가져오기 작업을 제공합니다.

편집기는 글로벌 디바운스 기간 이후 일반 필드 변경 사항을 자동 저장합니다. 유효성 검사 오류는 상태/토스트 피드백으로 보고됩니다. 유효하지 않은 일반 값은 관련 없는 설정으로 자동 변환되지 않습니다. 고정된 그룹은 일반 편집 컨트롤을 비활성화합니다.

확장 프로그램에는 사용자가 볼 수 있는 피드백 화면도 있습니다.

| 표면 | 기능적 목적 |
| --- | --- |
| 사용설명서 | 확장 프로그램에서 이 참조를 엽니다. |
| 언어 선택기 | 확장 인터페이스 언어를 선택합니다. |
| 설정 | 위에서 설명한 전역 설정을 엽니다. |
| 상태/토스트 피드백 | 보고서는 저장, 가져오기, 검증 및 작업 결과를 보여줍니다. |
| 페이지 내 타이머 오버레이 | 디스플레이 범위에 있는 활성 일반 타이머/카운트다운 항목과 사용자 정의 타이머를 표시합니다. 여러 항목이 공존할 수 있습니다. |
| 페이지 내 로그 표면 | 전역 설정에서 허용하는 경우 사용자 지정 로그, 경고 및 오류 호출을 받습니다. |
| 사용자 정의 로그 | 규칙으로 생성된 팝업 표시 항목에 대한 실시간 활동 로그입니다. 삭제 및 다운로드가 가능합니다. |

사용자 정의 그룹의 경우 규칙 필드에 소스 텍스트가 저장됩니다. 먼저 실행은 규칙 구문 실행 전을 수행하고 성공할 때만 소스를 로드합니다. 또한 편집기는 텍스트가 변경될 때 로컬 소스 Linting을 수행합니다. 눈에 보이는 **Let AI Code** 컨트롤은 프롬프트 필드를 열고 사용자의 요청, 현재 규칙 및 현재 사용자 지정 규칙 API에 대해 생성된 참조가 포함된 코드 생성 번들을 복사합니다. AI 서비스에 접속하거나 자동으로 규칙을 변경하지 않습니다.

템플릿 컨트롤은 템플릿 브라우저를 엽니다. 템플릿이 배송되면 제목, 설명, 태그, 매개변수 및 생성된 미리보기가 포함됩니다. 이를 적용하면 확인 후 현재 규칙 텍스트가 대체됩니다. 현재 제공된 템플릿 카탈로그가 비어 있습니다. 브라우저는 향후 선별된 템플릿에 계속 사용할 수 있으며 활성 규칙의 소스로 처리되어서는 안 됩니다.

## 5. 사용자 정의 규칙 언어

### 5.1 규칙 소스 양식

사용자 정의 그룹의 소스는 JavaScript입니다. **실행** 시 Vault는 이전 활성 소스에서 생성된 그룹의 이전 등록 및 상태를 제거한 다음 새 소스를 로드합니다.

소스는 다음 중 하나일 수 있습니다.

1. a function expression accepting events and helpers; or
2. 제공된 이벤트(또는 레거시 이벤트) 및 도우미 변수를 사용하는 간단한 설명입니다.

```js
// Function-expression form
(events, helpers) => {
  events.on("openWebEvent", "welcome", (event, h) => {
    h.log("Opened", event.url);
  });
}
```

```js
// Bare-statement form
events.on("openWebEvent", "welcome", (event, h) => {
  h.log("Opened", event.url);
});
```

Run은 JavaScript 구문/실행 전 검사를 수행하고 성공한 경우에만 현재 소스를 활성화합니다. 텍스트 저장과 텍스트 실행은 의도적으로 다릅니다. 활성 이벤트 소스가 되지 않고도 규칙을 저장할 수 있습니다.

사용자 정의 그룹이 다시 실행되거나, 비활성화되거나, 삭제되거나 명시적으로 중지되면 활성 소스가 언로드됩니다. 재실행하면 등록이 시작되기 전에 규칙의 핸들러, 타이머, 패널, 지속성 버킷 및 규칙 생성 플랫폼 조건자가 지워집니다. 샌드박스 복구는 활성 소스를 다시 로드할 수 있습니다. 따라서 규칙 작성자는 등록을 멱등성으로 만들어야 합니다.

### 5.2 실행 모델 및 안전한 가정

Custom rules are event registrations, not a continuous script loop. Register handlers during rule initialization, then respond to events.

각 핸들러는 다음을 수신합니다.

```js
(event, helpers) => {
  // event: the currently dispatched event object
  // helpers: the public Vault Custom-rule API
}
```

이벤트 핸들러는 숫자 우선순위를 내림차순으로 실행합니다. 동일한 우선순위는 등록 순서를 사용합니다. 동일한 이벤트 유형과 ID를 다시 등록하면 핸들러를 교체할 수 있습니다. 하나의 사용자 지정 그룹에 등록된 핸들러는 최대 1,000개입니다.

Vault는 한 핸들러의 활성 작업을 약 1초로 제한합니다. 1분 이내에 동일한 그룹에 대해 3번의 기한 초과가 발생하면 규칙이 격리됩니다. Vault는 문제가 있는 핸들러를 반복적으로 실행하는 대신 규칙을 비활성화합니다. 바쁜 대기, 무제한 루프, 동기 폴링 또는 이벤트당 엄청난 수의 변형/로그를 사용하지 마십시오.

파견당 Vault는 최대 다음을 허용합니다.

| 아이템 | 최대 |
| --- | --- |
| 규칙 로그 항목 | 200 |
| 게시된 이벤트 | 64 |
| DOM 작업 | 256 |
| 행동/의도 | 256 |
| 그룹당 패널 | 24 |
| 하나의 패널에 있는 컨트롤 | 32 |
| 선택/라디오 제어 옵션 | 64 |

초과 로그, 게시된 이벤트, DOM 작업 및 인텐트 항목이 삭제될 수 있습니다. 사용자 정의 규칙은 전달되는 초과 항목에 의존해서는 안 됩니다.

### 5.3 내장된 이벤트 유형

다음 이벤트 유형 문자열이 내장되어 있습니다. 규칙은 밑줄로 시작하지 않는 한 비어 있지 않은 자체 유형 문자열을 사용할 수도 있습니다.

| 이벤트 유형 | 전송된 경우 | 중요 데이터 |
| --- | --- | --- |
| 틱이벤트 | 전역 틱 속도 설정에서 주기적 틱을 공유합니다. | 가능한 경우 현재 페이지/탭 컨텍스트입니다. 개별 핸들러의 속도를 제한하려면 IntervalMs 등록 옵션을 사용하십시오. |
| 오픈웹이벤트 | 최상위 레벨 페이지를 규칙에 사용할 수 있게 됩니다. | URL, 호스트 이름, 탭/페이지 ID, 시간. |
| closeWeb이벤트 | 최상위 페이지/탭이 닫힙니다. | 가능한 경우 URL/호스트 이름 컨텍스트. |
| webChanged이벤트 | 동일한 URL 다시 로드를 포함한 커밋된 최상위 탐색입니다. | 데이터에는 이전 URL/호스트 이름과 isFirstLoad, isReload 및 sameDomain과 같은 탐색 플래그가 포함됩니다. |
| 타이머 종료됨 | 사용자 정의 타이머가 만료된 상태로 변경됩니다. | 데이터: 타이머Id, 디스플레이이름, 방향, 현재Ms. 타이머를 소유한 그룹에게만 전달됩니다. |
| 스누즈프레스 | 사용자는 이 사용자 정의 그룹에 대해 스누즈 시작을 누릅니다. | 규칙은 응답을 소유합니다. 일반적인 다시 알림 대체는 수행되지 않습니다. |
| 패널이벤트 | 렌더링된 사용자 정의 패널에는 상호 작용이 있습니다. | 데이터 및 편의 필드에는 패널/컨트롤/이벤트/값 정보가 포함됩니다. |
| 로컬파일이벤트 | 요청된 로컬 ​​파일 작업이 완료됩니다. | 데이터 및 편의 필드에는 requestId, 경로, 결과, 바이트, 항목 및 오류가 포함됩니다. |
| pageHeartbeat이벤트 | 탭이 표시되는 동안 약 250ms마다 표시되는 페이지 하트비트입니다. | elapsedMs는 표시 페이지 경과 시간입니다. 범위가 지정된 사용자 정의 타이머는 등록된 핸들러 없이도 자동으로 사용합니다. |

### 5.4 이벤트 레지스트리 API

함수 스타일 소스에 대한 첫 번째 인수는 이벤트 레지스트리입니다. 베어 스테이트먼트 소스에서는 이벤트와 이벤트 모두 이 레지스트리를 참조합니다.

| 방법 | 계약 |
| --- | --- |
| events.on(type, id, handler, options) | Register a handler. Returns true when accepted, false for invalid/capped registrations. |
| events.register(type, id, handler, options) | Alias of on. |
| events.off(type, id) | Unregister a handler. Returns whether something was removed. |
| events.unregister(type, id) | Alias of off. |
| events.unregisterAll(type) | Remove all handlers owned by this group for that event type. Returns the number removed. |
| events.getEvent(type, id) | Return the registered function for this group/id, or null. |
| events.getEvents(type) | Return an object mapping this group's handler ids to functions. |
| events.countRegistered(type) | Return this group's number of registrations for type. |
| events.emit(type, data, options) | Queue a synthetic event. |
| events.post(type, data, options) | Alias of emit. |

선택적 핸들러 옵션 개체는 다음을 지원합니다.

| 옵션 | 의미 |
| --- | --- |
| 우선순위 | 숫자 순서. 더 높은 값이 더 낮은 값보다 먼저 실행됩니다. 기본값은 0입니다. |
| 간격Ms | 정수. TickEvent의 경우에만 핸들러의 이전 호출 이후 이 시간이 경과할 때까지 호출을 억제합니다. |

합성 이벤트는 기본적으로 그룹 범위로 지정됩니다. 방출 그룹에 속한 핸들러만 이를 수신합니다. 동일한 유형을 등록한 모든 규칙에 이벤트를 보내려면 {scope: "global" }을 사용하세요. 이벤트 이름 앞에 밑줄을 사용하지 마십시오. 그것은 예약되어 있습니다.

### 5.5 이벤트 객체

모든 핸들러는 공통 필드가 있는 변경 가능한 이벤트 객체를 받습니다.

| 분야/방법 | 계약 |
| --- | --- |
| 유형 | 이벤트 유형 문자열. |
| 그룹ID | 수신자 사용자 정의 그룹 ID입니다. |
| 탭 ID, 페이지 ID | 사용 가능한 경우 브라우저 식별자 그렇지 않으면 null입니다. |
| URL, 호스트 이름 | 현재 최상위 URL 및 호스트 이름 또는 빈 문자열입니다. |
| 시간 | 디스패치 시간 객체의 복사본 또는 null입니다. |
| 데이터 | 이벤트별 페이로드 또는 null입니다. |
| 방지기본() | 디스패치를 ​​페이지 차단 작업으로 표시합니다. 페이지는 현재 리디렉션 링크/결과가 있는 경우 해당 페이지로 리디렉션됩니다. 그렇지 않으면 Vault는 일반 종료/대체 경로를 사용합니다. |
| 중지 전파() | 현재 이벤트 전달에 대한 이후 핸들러를 중지합니다. |
| setResult(값) | 숫자 또는 문자열 결과를 저장합니다. 비어 있지 않은 문자열은 리디렉션 대상으로 처리됩니다. 결과 1은 누적된 PreventDefault 결과를 억제합니다. |
| getResult() | 이 이벤트 개체에 의해 설정된 결과 또는 null을 반환합니다. |
| 게시물(유형, 데이터, 옵션) | Events.post와 동일한 범위 규칙을 사용하여 합성 이벤트를 대기열에 추가합니다. |
| setRedirectLink(url) | 이 디스패치에 대한 리디렉션 URL을 설정하세요. 문자열이 아닌 입력에 대해서만 false를 반환합니다. |
| getRedirectLink() | 이 디스패치의 리디렉션 URL 또는 빈 문자열을 읽습니다. |
| 닫기(ID) | 탭 닫기를 요청합니다. 숫자는 탭 ID이고 문자열은 URL을 식별하며 생략된 값은 활성 탭을 대상으로 합니다. |
| 블록(ID) | 세션 전용 동적 사이트 차단 패턴을 추가합니다. 문자열 ID가 없으면 이벤트 호스트 이름을 사용합니다. |
| 차단 해제(ID) | 세션 전용 동적 사이트 차단 패턴을 제거합니다. 문자열 ID가 없으면 이벤트 호스트 이름을 사용합니다. |
| 열기() | 브라우저 확장 기능이 작동하지 않습니다. 응용 프로그램을 시작할 수 없습니다. |

핸들러는 임의의 추가 속성을 이벤트에 연결할 수 있습니다. 해당 이벤트 개체가 활성화되어 있는 동안 event.custom을 통해 읽거나 할당된 이름으로 직접 읽습니다. 이는 지속적인 상태가 아니며 교차 이벤트 저장소도 아닙니다.

panelEvent의 경우 panelId, controlId, eventName, value, value, key, code 및 keyInfo와 같은 편의 필드가 추가됩니다.

localFileEvent의 경우 eventName, action, path,directoryPath, requestId, ok, text, value, items, presents, bytes 및 error와 같은 편의 필드가 추가됩니다.

### 6.2 타이머 도우미

Get it with helpers.getTimerHelper(). Timers are rule-owned counters. They may be displayed in Vault's page overlay, but they never block on their own.

옵션 생성/가져오기:

| 옵션 | 의미 |
| --- | --- |
| 아이디 | 비어 있지 않은 타이머 ID가 필요합니다. |

| 방법 | 행동 |
| --- | --- |
| 생성(옵션) | 타이머를 생성/교체하고 상태를 재설정합니다. id 또는 null을 반환합니다. |

## 8. 사용자 정의 규칙 작업 레시피

다음 예시는 튜토리얼이 아닌 공개 구성의 사양입니다.

### 8.1 시작 페이지 리디렉션

```js
(events, helpers) => {
  events.on("openWebEvent", "redirect-distracting-search", (event, h) => {
    const domain = h.getDomainHelper();
    if (!domain.isSearchPage(event.url)) return;
    event.setRedirectLink(h.getRedirectionHelper().createMessageUrl("Return to your planned task."));
    event.preventDefault();
  });
}
```

### 8.2 명시적 블록을 사용한 표시 시간 카운트다운

```js
(events, helpers) => {
  const timer = helpers.getTimerHelper();
  timer.create({
    id: "reading-budget",
    displayName: "Reading budget",
    direction: "backward",
    currentMs: 10 * 60 * 1000,
    scope: (url) => url.includes("example.com")
  });

  events.on("timerEnded", "stop-at-zero", (event) => {
    if (event.data?.timerId !== "reading-budget") return;
    event.setRedirectLink("about:blank");
    event.preventDefault();
  });
}
```

### 8.3 패널에서 피드 조건자 변경

```js
(events, helpers) => {
  const panel = helpers.getPanelHelper();
  const youtube = helpers.platform("youtube");

  panel.create({
    id: "feed-filter",
    title: "Feed filter",
    controls: [{
      id: "hide-sponsored",
      type: "toggle",
      label: "Hide sponsored items",
      value: true,
      onChange: (event, h) => {
        const api = h.platform("youtube");
        if (event.value) {
          api.hide("videos", (item) => item?.sponsored === true);
        } else {
          api.show("videos");
        }
        api.rescan();
      }
    }]
  });

  youtube.hide("shorts", () => true);
}
```

활성 플랫폼 표면에서 제공되는 플랫폼 스냅샷/항목 값에 대한 조건자를 작성해야 합니다. 플랫폼이 필드를 안정적으로 식별할 수 없는 경우 조건자는 값이 true라고 가정하는 대신 페일오픈(fail open)해야 합니다.

## 9. 로컬 폴더 요청 프로토콜

로컬 폴더 작업은 즉각적인 파일 I/O가 아닙니다. 전체 기능 순서는 다음과 같습니다.

1. 사용자가 전역 설정에서 폴더를 선택합니다.
2. 규칙은 요청을 대기열에 추가하고 요청 ID를 받습니다.
3. Vault는 승인된 폴더 기능에 작업을 수행하도록 요청합니다.
4. Vault는 동일한 사용자 정의 그룹에 localFileEvent를 보냅니다.
5. 핸들러는 event.requestId를 원래 요청 ID와 연관시킵니다.

성공적인 읽기는 텍스트 파일의 텍스트 또는 JSON의 값으로 완료됩니다. 목록은 항목을 반환합니다. 존재 반품이 존재합니다. 쓰기/추가는 해당되는 경우 바이트를 제공합니다. 실패는 ok false 및 오류를 제공합니다. 규칙은 다시 로드, 브라우저 다시 시작 또는 권한 취소 후에도 선택한 폴더가 승인된 상태로 유지된다고 가정해서는 안 됩니다.

## 10. 사용자 정의 규칙 안전 및 실패 의미 체계

### 10.1 컴파일 및 실행 오류

구문 보고서 컴파일 실패를 확인하세요. Run은 등록 중에 런타임 오류를 보고할 수도 있습니다. 함수형 소스에 구문 오류가 있는 경우 Vault는 이를 무해한 기본 명령문으로 자동으로 처리하지 않습니다.

빈 소스에는 핸들러가 없습니다. 비활성 사용자 정의 규칙으로 유효하지만 구성된 사용자 정의 작업을 수행하지 않습니다.

### 10.2 핸들러 오류

한 핸들러의 예외는 전체 이벤트 전달에서 격리됩니다. 진단 출력입니다. 나중에 핸들러가 마술처럼 성공하도록 만들지는 않습니다. 좁은 핸들러를 사용하고 조치 가능한 오류를 기록하십시오.

### 10.3 격리

반복되는 기한 초과 또는 등록 중 초과 실행이 발생한 후 Vault에서는 맞춤 그룹을 격리할 수 있습니다. 격리는 그룹을 비활성화하고 중단 이유를 기록합니다. 소스를 수정하고 저장한 후 명시적으로 다시 실행하여 활성 등록을 복원합니다.

### 10.4 브라우저/페이지 제한

사용자 정의 규칙은 무제한 확장 API를 수신하지 않습니다. 특히:

- DOM 선택기는 변경된 플랫폼에서 아무것도 찾을 수 없습니다.
- 탐색, 탭 닫기 및 화면 동작은 브라우저 성능에 따라 달라집니다.
- 확장 프로그램은 기본 애플리케이션을 열 수 없습니다.
- 로컬 폴더 작업에는 사용자가 부여한 폴더와 지원되는 파일 형식이 필요합니다.
- 이벤트 핸들러는 표시 시간 하트비트를 계속 생성하는 보이지 않는 페이지에 의존할 수 없습니다.
- 페이지는 규칙과 관계없이 콘텐츠 스크립트를 다시 로드하거나 탐색하거나 삭제하거나 무효화할 수 있습니다.
- 규칙으로 생성된 동적 사이트 블록은 영구 사이트 그룹 편집이 아닌 세션 상태 작업입니다.

## 11. 웹앱 브릿지

브라우저 확장 프로그램은 ws://127.0.0.1:8787의 호환 로컬 Vault 허브에 자동으로 연결을 시작합니다. 사용자 연결 스위치는 없으며 프로토콜 호환성이 필요합니다.

Vault는 먼저 빠르게 탐색한 다음 확장 프로그램이 실행되는 동안 느린 재연결 시도를 계속합니다. 자동 전송 자체가 그룹을 병합하지는 않으며 그룹 연결과 연결 해제는 명시적으로 유지됩니다.

### 11.1 그룹 연결하기

그룹은 이름과 유형이 일치하고 연결 가능한 경우에만 연결이 가능합니다. 사용자는 참여 프로그램을 명시적으로 선택/링크합니다. 연결된 그룹은 클러스터를 형성합니다. 연결을 끊으면 로컬 그룹 데이터가 그대로 유지됩니다. 실시간 동기화가 중지됩니다.

브리지는 일반 차단 모드, 허용/재설정 값, 다시 알림 설정, 활성 날짜/창, 상태/선택/기간 고정, 홈페이지 정책, 허용 목록 설정, 대체 URL 및 다음으로 건너뛰기 정책을 포함하여 지원되는 연결 그룹에 대한 공유 스칼라 정책을 동기화합니다. 또한 클러스터 구성원의 사용 및 일시 중지 상태를 조정합니다.

브릿지는 모든 제품별 필드, 플랫폼 선택기, 사용자 정의 소스 텍스트 또는 브라우저별 기능을 다른 프로그램으로 전송할 수 있다고 약속하지 않습니다. 브리지가 연결되어 있는 동안에도 그룹은 로컬 상태로 유지되고 연결 해제될 수 있습니다.

고정 브리지 클러스터에서는 조정된 돌연변이가 필요한 고정 상태 작업을 위해 모든 관련 구성원이 온라인 상태여야 합니다. 연결은 클라우드 백업이나 원격 제어 채널이 아닌 로컬 전송입니다.

## 12. 메인테이너를 위한 검증 체크리스트

릴리스를 감사하거나 동작을 재현할 때 이 체크리스트를 사용하십시오.

1. 그룹에 비어 있지 않은 고유 이름, 올바른 유형, 활성화된 상태 및 의도된 목록/순서가 있는지 확인합니다.
2. 일반 그룹의 경우 활성 평일, 유효한 현지 시간 창, 활성 스누즈 없음, 고정되지 않은 편집 상태를 확인합니다.
3. 사이트 그룹의 경우 정확한 호스트, 하위 도메인 및 목록 외부의 호스트(허용 목록의 경우)를 테스트합니다.
4. 플랫폼 그룹의 경우 페이지 수준 일치, 대상 항목/카드 일치, 작성자 모드, 콘텐츠 양식 모드 및 활성화된 각 표면 숨기기를 별도로 테스트합니다.
5. 시간이 지정된 일반 그룹의 경우 표시 페이지 발생, 허용 만료 또는 카운트업 비차단 동작 및 재설정 간격을 확인합니다.
6. 사용자 정의 규칙의 경우 구문 검사를 실행하고, 실행하고, 핸들러 수/로그를 검사하고, 등록된 모든 내장 이벤트를 테스트한 다음 다시 로드/탐색을 테스트합니다.
7. 범위 경계와 0에서 각 사용자 지정 타이머를 테스트합니다. 규칙에 명시적인 블록이 있는지 확인하세요.
8. 각 컨트롤 값, 비활성화된 상태, 제출/취소/닫기 작업 및 panelEvent 핸들러를 사용하여 패널을 테스트합니다.
9. 성공하기 전에 로컬 폴더 실패를 테스트합니다. 선택한 폴더 없음, 권한 취소, 잘못된 경로, 지원되지 않는 확장, 읽기/쓰기 승인.
10. 동기화 또는 고정 조정에 의존하기 전에 자동 전송 시작, 연결/연결 해제 그룹 및 오프라인 클러스터 구성원을 테스트합니다.

## 13. 버전 관리 규칙

이 영어 파일은 유지 관리되는 소스 매뉴얼입니다. 현지화된 매뉴얼은 이를 번역한 것이므로 기능 문서 업데이트 후 재생성이 필요할 수 있습니다. 제품 소스는 구현 수준의 모호성에 대한 정식 진실로 남아 있습니다.
